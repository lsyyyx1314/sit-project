## 摘要

路径验证（path verification）使接收方或控制器能够判定数据包是否沿预定路径转发，
是网络可信转发的基础能力。现有路径验证方案大多建立在单路径假设之上；在软件定义
网络（SDN）多路径转发环境中，同一流的数据包可能被分散到多条合法路径，逐路径校验
带来随候选路径数增长的控制器开销，逐跳追加路径信息又带来随跳数增长的验证头膨胀，
且已有方案普遍缺少异常发生位置的定位能力。

本文提出 MPV-2：一个面向 SDN 多路径场景的路径验证机制族，包含三个递进的层次——
基础包级多路径验证 BPMV、一致性增强包级验证 CPMV 与流级压缩验证 CFMV。其核心
观察是：把随机性从指数项搬到线性项（`h = H(nonce)` 公开、单跳贡献
`c_i = (a_i + b_i·h) mod p`、逐跳以位置权重 ρ 累积），则控制器期望值可以折叠为
`E(P) = A_P + B_P·h`，与 nonce 无关、可按路径预计算。由此直接导出三个性质：

1. **定长验证头**：16 字节（nonce 56 bit + V 64 bit + tag 8 bit），不随跳数 h 与
   候选数 k 膨胀（h=16 时较逐跳追加式省 75%）；
2. **一次判定**：tag 模式 O(1) 且与 k 无关（k=64 实测 0.33 µs），同测试床下
   逐跳 MAC 链基线在 k=64 需 482.8 µs（约 1120×）；
3. **流级压缩**：线性性给出恒等式 `ΣV = N·A + B·Σh`，出口交换机按 (流, tag)
   聚合 `(N, Σh, ΣV)` 三元组，控制器每窗口一次判定，与窗口内包数 N 无关
   （N=4096 实测 0.05 µs）；同等控制器负载（1/64 逐包）下概率采样基线漏检
   98.4%，CFMV 保持 100% 检出。

我们进一步给出与验证协同的异常定位方法学：逐跳取证值沿实际路由对照，篡改跳以
观测值为基准避免下游误标、位置偏离标注改道跳，可同时报出多故障的全部嫌疑交换机；
大样本实验（随机路径 5–9 跳、随机故障位置）中单故障、双故障的嫌疑集精确命中率
均为 100%，诚实流零误标；对照实验证明合法集合内改道可由候选对比定位，而集合外
篡改只有逐跳取证能定位（0% vs 100%）。

我们在 C++17 上实现了完整原型（软件交换机、控制器、验证内核、演示 APP 与实验
套件），在 4 台软件交换机的 netns 拓扑上通过 7 轮端到端场景（含链路故障切换与
多重故障），十类结构性攻击 ×10⁴ 次检出率 100%，诚实流通过率 100%，申报书原式
在同一方法学下检出 0%（已证伪）。

**关键词**：软件定义网络；多路径；路径验证；定长验证头；流级压缩；异常定位

## 1 引言

### 1.1 背景与动机

SDN 将控制平面与数据平面分离，控制器基于全局视图计算多条合法路径并下发转发规则，
实现负载均衡与故障切换（ECMP、B4、Hedera、CONGA 等）。然而转发规则的正确下发
不等于正确执行：链路故障、配置错误或被攻陷的交换机都可能使数据包偏离合法路径
集合。路径验证要求**数据平面在转发过程中**生成可被控制器校验的证据，从而判定
每个包（或每条流）是否沿合法路径集合中的某一条转发。

已有的路径验证工作（Icing、Hummingbird 等）默认单路径转发。多路径场景引入三个
新问题：

- **验证对象从路径变成集合**：控制器不知道每个包实际走了哪条候选路径，若对每条
  候选逐一校验，开销随 k 线性增长；
- **验证头膨胀**：逐跳追加路径信息使验证头随 h 线性（甚至按设计指数式）增长，
  挤占载荷、消耗带宽；
- **异常不可定位**：合规/异常的二元判定无法回答"哪一台交换机出了问题"。

### 1.2 贡献

1. **MPV-2 构造**：把随机性放在线性项的定长验证头方案，控制器期望值与 nonce
   无关、可预计算，判定 O(1) 且与 k 无关；多路径场景下"多条路径、一次判定"
   （CPMV）。在申报书原式（模幂消去随机数）被证明恒真退化（伪造接受率 100%）
   的前提下，这是对"多路径可验证"目标的可行重构。
2. **CFMV 流级压缩**：由期望值对 h 的线性性直接导出流级恒等式，出口聚合三元组
   `(N, Σh, ΣV)`，控制器每窗口一次判定；通信开销降至逐包上报的 0.46%–14%
   （窗口 250–8），判定与 N 无关。配合 nonce 重放窗口保持抗重放性。
3. **异常定位方法学**：逐跳取证 + 首分歧定位 + 多故障全部嫌疑报出 + 黑洞失联
   发现；并用对照实验界定取证机制的适用边界（闭集内改道 vs 闭集外篡改）。
4. **完整原型与实验套件**：纯 C++17（无脚本语言），软件交换机（AF_PACKET）、
   控制器、演示 APP、一键实验套件；7 组结题实验 + 4 组补充实验自动生成报告与
   图表，全部数字可复现。

## 2 相关工作

**静态网络验证**：Anteater（布尔可满足性）、HSA（头空间分析）、Batfish、
Minesweeper（SMT）等在配置与转发表层面验证不变量；VeriFlow、NetPlumber 将验证
增量化和实时化。它们验证"规则"，不验证"每个包的实际轨迹"。

**数据面遥测与记录**：ATPG 主动注入测试包；NetSight 用包历史重构转发轨迹；
Everflow 选择性镜像。这些方法开销随覆盖面增长，难以在多路径环境对全部流量持续
验证。

**路径验证**：Icing 首次在终端与中间节点间嵌入逐跳标记，验证头随跳数增长；
Hummingbird 以隐藏等概率采样降低逐跳开销但仍面向单路径；L-PVS 面向 SDN 以固定
长度头 + 计数器优化存储，但仍以单路径为主。Atlas 首次面向多路径验证提出路径
指纹 + 概率采样；SwiftParade 解决突发流下的验证失效。概率采样路线以**漏检率**
换控制器负载——本文的对照实验定量刻画了这一代价（负载 1/64 时漏检 98.4%），
并给出不漏检的替代路线（流级聚合）。

**可编程数据平面**：P4/INT 使数据面可编程并支持带内遥测；PINT 将遥测开销压到
每包少量比特但面向测量而非安全判定。这些是 MPV-2 数据面逻辑（逐跳 O(1) 更新）
的天然部署载体。

**多路径路由**：ECMP、CONGA、HULA、LetFlow、Hermes 等解决"如何选路"；本文解决
"所选路径是否被真实执行"。

## 3 问题模型与设计目标

### 3.1 网络与攻击模型

网络建模为有向图，控制器为每条流维护合法候选路径集合 `P_f = {P_1, …, P_k}`。
每台交换机持有与控制器共享的密钥材料（身份密钥 + 端口密钥）；验证头随包转发，
出口交换机（或聚合点）把验证信息上报控制器。

攻击者可以控制若干交换机或链路，能力包括：改变出/入端口（改道）、绕过某跳
（旁路）、交换跳序、删除/插入/替换跳、截断路径、篡改验证头比特、复制重放帧。
攻击者不知道密钥；至少存在一跳诚实交换机（安全性的必要条件，与 Icing 等一致）。
控制器可信。

### 3.2 设计目标

| 目标 | 含义 | 对应机制 |
|---|---|---|
| 能验证 | 合法路径集合内任一路径上的诚实包通过；集合外行为检出 | BPMV |
| 验证快 | 判定不随 k、h 增长 | CPMV（tag 模式 O(1)） |
| 开销低 | 验证头定长；通信与状态不随流量线性膨胀 | 定长头 + CFMV |
| 可定位 | 失败时给出嫌疑交换机，多故障全部报出 | 逐跳取证定位 |

## 4 MPV-2 构造

### 4.1 申报书原式的不可行性（反例）

申报书原式 `g^(w·s_m) ≡ f_s^w (mod p2)`，`w = lcm(p1−1, p2−1)`。由于 `w` 是
`p2−1` 的整数倍，欧拉定理给出 `g^w ≡ 1 (mod p2)`，判定式两端恒为 1。在 16/32/64
位三档参数下各 200 次随机试验：伪造包接受率 100%，诚实流通过率 0%。根因是
方法论的：**随机数一旦进入指数，就无法在不暴露它的前提下被消去**——消去指数中
随机数的欧拉定理同时把路径信息也消掉了。这一反例把设计空间收窄为：随机性必须
在线性项上。

### 4.2 构造

密钥派生：控制器以种子派生每台交换机的身份密钥与各端口密钥，端口密钥
`ks_i = K(sid_i, in_i, out_i)` 绑定"哪台交换机的哪个端口"。

单跳贡献与逐跳累积（数据面，每跳 O(1) 次模乘）：

```
h    = H(nonce)                    公开哈希（BLAKE2b，56-bit nonce → Z_p）
c_i  = (a_i + b_i·h) mod p         a_i, b_i 由 ks_i 派生
V  ← V + c_i · ρ^(i−1) mod p       ρ 为公开位置权重，绑定跳序
```

控制器期望（流建立时对每条候选路径预计算一次）：

```
E(P_j) = A_j + B_j · h,   A_j = Σ a_i·ρ^(i−1),  B_j = Σ b_i·ρ^(i−1)
```

验证头定长 16 字节：`nonce(56) ‖ V(64) ′ tag(8)`。

### 4.3 三层机制

- **BPMV（基础包级）**：控制器对候选集逐条校验 `V == E(P_j, h)`，O(k)；
  或在 tag 不可信时作为扫描兜底。
- **CPMV（一致性增强）**：tag 记录实际走的候选编号，控制器只校验
  `V == E(P_tag, h)`，O(1) 与 k 无关——"多条路径、一次判定"。
  篡改 tag 的包会落到错误期望上被检出；tag 本身被控制器以候选集校验兜底
  （scan 对照），不影响检出率。
- **CFMV（流级压缩）**：由线性性，窗口内 N 个包满足

  ```
  Σ V = N·A_tag + B_tag · Σ h
  ```

  出口交换机按 (流, tag) 聚合 `(N, Σh, ΣV)` 三个 64 位数，控制器每窗口一次
  判定，与 N 无关。**必须配合 nonce 重放窗口**：聚合是可加的，重放合法包会
  同时抬高三元组；控制器以定长 nonce 环（4096）去重。

### 4.4 安全性讨论

- **伪造**：不知道密钥时，(a_i, b_i) 在 Z_p 上均匀，单次伪造成功率 1/p
  （p = 2^64−59，64-bit 域）；结构攻击（改端口/旁路/换序/插删跳）改变的是
  (a_i, b_i) 的取值或位置权重 ρ^(i−1)，期望值随之改变，检出率实测 100%
  （十类 ×10⁴）。
- **重放**：逐包口径下 nonce 窗口直接判重；CFMV 口径下重放抬高聚合三元组，
  由 nonce 窗口去重保证不叠加。端到端实测 60 条重放全部拦截、诚实包零误伤。
- **与困难问题的关系**：本方案的安全性建立在 PRF（keyed BLAKE2b）与模乘域
  的均匀性上，未做密码学归约；128-bit 域参数档为直筒替换（`unsigned __int128`
  中间量已就位）。这一局限在第 8 节明示。

### 4.5 复杂度

| 项 | MPV-2 | 逐跳 MAC 链（Icing 类） | 概率采样（Atlas 类） |
|---|---|---|---|
| 数据面每跳 | 1 次模乘 + 1 次哈希 | 1 次带密钥哈希 + 追加 8B | 同所属基线 |
| 验证头 | 16B 恒定 | 8B/跳（h=7 时 63B） | 16B（被采样包） |
| 控制器判定 | O(1)（tag）/ O(k)（scan） | O(k·h) 次哈希 | O(ρ) 漏检为代价 |
| 检出率 | 100% | 100% | ≈ ρ |
| 逐流状态 | 出口 24B/流 + 定长 nonce 窗 | 无（头膨胀换） | 无（漏检换） |

## 5 异常定位方法学

### 5.1 逐跳取证与首分歧定位

交换机可开启 `--trace`，在本跳之后把实际 `(sid, in, out, pos, V_after)` 写入
取证文件。控制器验证失败时沿实际路由逐跳对照：

- **篡改检查**：第 i 跳期望 `V̂_i = carry_{i-1} + c_i·ρ^(i−1)`，其中
  `carry_{i-1}` 用**观测值**——篡改偏移 δ 会随帧传播，若用纯净累计值会把
  下游诚实交换机也误标；
- **位置检查**：实际 (sid,in,out) 与声称路径第 i 跳不一致 → 改道/改端口，
  嫌疑 = 声称路径第 i 跳交换机；
- **出口篡改**：取证全程吻合但出口上报不符 → 出口交换机本身嫌疑；
- **黑洞失联**：取证出现但出口未上报的 nonce = 在某跳之后失联，结合候选对比
  给出改道跳。

多故障：上述检查逐跳独立进行，同时报出全部嫌疑（改道跳 + 每个篡改跳）。

### 5.2 取证的适用边界（对照实验结论）

- 合法集合内的改道（tagflip 类）：有/无取证都能定位（无取证时由候选对比给出
  路由分歧点）；
- 集合外篡改（改端口/改头）：无取证无法定位（scan 无候选可对，0%），取证定位
  100%。

取证本身有存储与 I/O 开销，工程上可只在异常流上触发（先由包级/流级判定发现
异常，再对该流开取证），这是演示 APP 与 e2e 采用的分工。

## 7 实验评估

环境：Ubuntu 24.04，g++ 13，VMware VM（4 vCPU），64 位素数域 `p = 2^64−59`。

> 本节数字由 `exp` 套件自动生成（`results/exp_report.md`），标注 † 的为本次
> 结题新增实验。

### 7.1 检出率与诚实接受（[1][2]）

十类结构性攻击 ×10000 次：S1–S10 检出率全部 100%；诚实接受 100%。
多候选集 k=2/8/16：攻击检出 / 诚实接受 均 100%。

### 7.2 控制器判定时延（[3]）

k ∈ {1..64}，tag 模式 0.31–0.33 µs 恒定（与 k 无关）；scan 随 k 线性
（k=64 时 0.76 µs）。

### 7.3 流级判定与控制器吞吐（[4]）

CFMV 判定 0.03–0.05 µs，与窗口 N 无关（N 至 4096）；控制器上报处理 7.7 万行/秒
（含双口径判定与行解析，多次实测区间 7.7–9.8 万），窗口 64 压缩 64×。

### 7.4 通信与头长开销（[5][6]）

流级聚合上报降至逐包上报的 0.46%–14%（窗口 250–8）；验证头恒定 16B，
h=16 时较逐跳追加式（4B/跳）省 75%。

### 7.5 端到端场景（[7]）

4 台软件交换机拓扑，7 类场景 ×5 轮全部通过：标签错配定位 s1、恶意改头定位 s2、
60 条重放全拦截、黑洞失联定位、流级压缩 40→2 次判定、链路故障切换零误报、
多重故障同时定位 {s1, s3}。

### 7.6 状态存储开销 †（[8]）

控制器期望表 O(k)（k=64 时 6.4KB 含路径索引）；nonce 窗口定长 32KB/方向；
出口 CFMV 聚合 24B/流，为逐流路径记录式（8B×h）的 1/2.3；数据面转发路径
0 逐流状态。

### 7.7 定位成功率 †（[9]）

随机路径 5–9 跳、随机故障位置、2000 样本：恶意改头（486）/ 路径改道（502）/
双故障（512）嫌疑集精确命中率均 100%（1500/1500），零误标，诚实流零误报。
取证对照见第 5.2 节（集合外篡改：有取证 100% / 无取证 0%）。

### 7.8 基线对比 †（[10]）

- 逐跳 MAC 链（Icing 类，同密钥体系）：判定时延随 k 线性，k=64 时 482.8 µs；
  MPV-2 tag 模式 0.43 µs——约 1120×；k=1 时 6.3 µs vs 0.33 µs（约 19×），
  差距随 k 线性放大。
- 概率采样（Atlas 类）：检出率 ≈ ρ；控制器负载 1/64 时漏检 98.4%；
  MPV-2+CFMV 同负载下 100% 检出。

### 7.9 规模扩展 †（[11]）

h ∈ {4,8,16,32}：数据面单跳均摊 1.72–1.81 µs（O(1)，不随 h 变化）；控制器
tag 判定恒定 0.33 µs 与 h 无关；期望预计算随 h 线性（5.7→45.4 µs）但仅为流
建立时一次；检出率 100% 不随规模退化。

## 8 局限与未来工作

1. **安全归约**：未给出基于困难问题的归约；下一步形式化 PRF 假设下的伪造
   概率上界，并补 128-bit 域参数档。
2. **数据面保真度**：原型为用户态 AF_PACKET 交换机（吞吐 ~3500 pps，比硬件低
   2–3 个数量级）；控制器判定吞吐（10 万行/秒）与数据面逐跳逻辑（O(1) 模乘）
   均已解耦实测。P4/BMv2 移植为后续工作，逐跳逻辑仅一条乘加，适配 P4 寄存器
   哈希约束是主要工程点。
3. **对比口径**：算法级基线（MAC 链、概率采样）为同测试床复现，系统级
   （Icing/Atlas 完整系统）对比仍为解析口径，未直接横比绝对数值。
4. **拓扑规模**：端到端拓扑为 4 台软件交换机（netns 资源约束）；算法层实验
   覆盖 k 至 64、h 至 32。
5. **控制器**：半在线（场景级候选集热切换，无持续拓扑发现）。

---

## 9 结论

把随机性放在线性项上，使多路径验证的三个经典矛盾——验证对象是集合、验证头
必须定长、判定必须一次完成——在同一构造下同时消解；流级压缩由线性性免费获得，
把逐包通信压到 0.46%–14% 而不引入漏检；逐跳取证把"发现异常"推进到"定位异常"，
并给出多故障下的全部嫌疑集合。原型与实验套件证明该机制可在真实网络栈
（AF_PACKET + netns）上端到端运行，全部数字可复现。
