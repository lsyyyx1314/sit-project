# 优化空间分析报告（M5.17 之后）

> 目的：回答「实现层与架构层是否还有优化空间，当代应用框架能带来什么」。
> 方法：通读全部源码与 §15–§19 既有优化记录 → 在 VM 上对**每一条候选优化做受控实测**，
> 以 612 黄金向量 + 716 项断言 + e2e R1–R7 为回归门槛，只采信有数据支撑的结论。
> 日期：2026-11-15；分支 dev（1f832a1）。

## 0 结论摘要

| 级别 | 发现 | 类型 | 预期收益 | 成本 |
|---|---|---|---|---|
| **P0-1** | TRACE 行 sid/port 字段**不校验**，越界值使控制器 `unordered_map::at` 抛异常崩溃（§1） | 安全/健壮性 | 消除控制器级 DoS | ~10 行 |
| **P0-2** | 取证表**单 nonce 条目数无上界**：`traces_[key].push_back` 只受 key 数约束（§1.4） | 安全/内存 | 消除内存放大 DoS | ~3 行 |
| **P1-1** | 编译旗标 `-O2 → -O3 -flto`：scan（BPMV）k=64 **0.69→0.26µs（≈2.6×）**、tag ≈1.2×、CFMV ≈1.4×（§2） | 性能 | 零代码改动 | 1 行 Makefile |
| **P1-2** | FLOW/TRACE 行仍走 istringstream（每行 2+ 次串拷贝），比逐包快路径慢 **1.6–1.9×**（§3） | 性能 | 该行型 ~40–90% | ~80 行 |
| **P1-3** | Makefile 头文件依赖手工维护（HDRS），漏更即静默漏编（§4.1） | 工程性 | — | 2 行 |
| **P2** | SSE 实时推送、`/metrics` 观测端点、NonceWindow 取模回卷、dashboard 集合无界等（§4/§5） | 工程/UX | 小 | 各 ~50 行 |
| **P3** | io_uring TX 批量、AF_XDP、P4/BMv2、CI+fuzz 入库（§5，当代框架对照） | 架构演进 | 数据面天花板 | 周级 |

全部建议**不改变任何输出语义**（除 P0 两项修复外），黄金向量与 e2e 门槛全程把关。
另：**PGO 与 `-march=native` 实测无增益**（§2.3），不建议引入；§16「实现层已无开销可削」
的结论在单次判定口径上仍然成立——本次找到的空间在**其口径之外**（旗标、行型、健壮性）。

## 1 P0：控制器可被伪造取证行击穿（新发现，含复现）

### 1.1 缺陷

`Controller::feed_trace`（`cpp/src/controller.cpp:181-197`）对 TRACE 行的
`sid / in_port / out_port` **不做任何边界校验**，直接存入取证表。
`Controller::localize_all`（`cpp/src/controller.cpp:246`）随后以
`contribution(kr_, hop, hh)` 计算期望值 → `KeyRing::port_key`
（`cpp/src/mpv2.cpp:101-106`）内是 `switches_.at(h.sid)`、`sk.ports.at(...)`
——**越界即抛 `std::out_of_range`，进程 terminate**。

### 1.2 威胁模型内的攻击面

项目威胁模型显式包含恶意交换机（`vswitch --evil`、M4.5）。但现有恶意模拟只篡改
验证头/重放；一个真正被控的交换机只需向上报/取证文件写**一行**

```text
TRACE 00:00:00:00:00:02 99 1 2 0 <nonce> 1 12345     ← sid=99 越界（部署只有 16 台）
```

当该 nonce 的包判定失败（或 dashboard 黑洞路径：取证有、出口无上报）触发定位时，
控制器崩溃。dashboard 以 **root** 运行并消费这些文件——单行即可击杀验证系统与演示台。
与恶意无关的触发面同样存在：多进程并发 append 的行交错、文件损坏都可能产生越界字段。

### 1.3 复现（VM 实测，2026-11-15）

```cpp
Controller ctl(20260501, {dir});                          // 1 条路径，5 跳
ctl.feed("TRACE 00:00:00:00:00:02 99 1 2 0 81985529216486895 1 12345");
ctl.feed("4 0 81985529216486895 999 00:00:00:00:00:02");  // acc 错误 → 走定位
// terminate called after throwing 'std::out_of_range' (unordered_map::at) — EXIT=134
```

对该缺陷做 ASan 下 50 万次/种子的畸形行模糊测试，`seed=12345` 在 50 万次内即命中——
触发概率与部署 16 台 × 4 端口的取值空间相比并不小。

### 1.4 同源缺陷：单 nonce 取证条目数无上界

`traces_[key].push_back(...)` 的规模控制只有 `traces_.size() > trace_cap_`
（**key 数**，2¹⁴）——单个 key（同方向同 nonce）的条目向量本身无界。
同一 nonce 洪灌 10⁷ 条 TRACE → 单 key ~200MB：内存放大型 DoS，与 M5.11 修复
（key 数上界）同源但漏掉了维度。

### 1.5 修复草案（两处，均在解析边界收口）

```cpp
// mpv2.h（部署边界常量化，消除散布在 8+ 处的 generate(16,4,...) 魔数）
inline constexpr uint32_t kMaxSwitches = 16;
inline constexpr uint32_t kMaxPorts    = 4;

// controller.cpp feed_trace：越界行不可能来自合法交换机 → 丢弃（定位退化为候选对比）
if (sid < 1 || sid > mpv::kMaxSwitches ||
    in_p < 1 || in_p > mpv::kMaxPorts || out_p < 1 || out_p > mpv::kMaxPorts)
  return ev;
// 条目数上限：合法取证每 nonce ≤ 路径最长跳数（exp[11] 上界 32，取 64 有余量）
auto& v = traces_[key];
if (v.size() < 64) v.push_back(HopTrace{sid, in_p, out_p, pos, v_after});
```

回归门槛：既有取证定位断言（716 项中第 4 组）+ 新增「越界 TRACE 行被拒」断言 +
最小复现用例转为 tests 用例。**建议在演示/论文实验任何对外运行前先落地本项。**

## 2 P1：编译旗标——零代码改动的最大单项收益

### 2.1 矩阵实测（VM，g++ 13.3，各 3 次取代表值；716/716 为硬门槛）

| 配置 | tag k=64 (µs) | scan k=64 (µs) | CFMV (µs) | NonceWindow (ns/次) | 正确性 |
|---|---|---|---|---|---|
| `-O2`（当前） | 0.34–0.35 | 0.69 | 0.06 | 28–32 | 716/716 |
| `-O3` | 0.28–0.35 | 0.52–0.70 | 0.06 | 28–29 | 716/716 |
| **`-O3 -flto`** | **0.27–0.32** | **0.26–0.30** | **0.04** | 28–29 | 716/716 **+ e2e R1–R7 全过** |
| `-O3 -flto -march=native` | 0.29–0.32 | 0.27–0.30 | 0.04–0.05 | 28–31 | 716/716 |
| `-O3 -flto`+PGO | 0.27–0.37（无稳定增益） | 0.26–0.35 | 0.04–0.06 | — | 716/716 |

**`-O3 -flto` 相对 `-O2`：scan ≈2.6×、tag ≈1.15–1.3×、CFMV ≈1.4×。**
机理：LTO 跨 TU 内联 `mulmod/addmod` 的梅森折叠与 `h_of` → `blake2b` 调用链，
消掉 verify 循环里的调用开销与重复装载；scan 的 64 次迭代放大了该收益。

### 2.2 建议

`cpp/Makefile` 一行改动 + 自动依赖（见 §4.1）：

```make
CXXFLAGS ?= -std=c++17 -O3 -flto -Wall -Wextra -Iinclude
```

### 2.3 负结论（同样有数据）

* **PGO**：训练后无稳定增益。热点是已 12 轮全展开的单次 blake2b 压缩——
  分支布局已无可优化空间，与 §16「计算下界」论证自洽。不值得引入双阶段构建复杂度。
* **`-march=native`**：本负载无 SIMD 价值（哈希/折叠为标量 64 位运算），
  实测与 LTO 持平，且破坏二进制可移植性。不推荐。
* **feed 吞吐不受旗标影响**：实测 O2 与 O3+LTO 持平（875 vs 873 ns/行，
  同机同批）——feed 瓶颈在 blake2b + 哈希表操作，非可内联算术。

## 3 P1：FLOW/TRACE 解析慢路径（M5.14 的遗留一半）

M5.14 只给**逐包行**做了手写快路径；FLOW/TRACE 行仍走
`std::istringstream`（`controller.cpp:41/45`），且 `feed_flow/feed_trace` 里
`ss.str().c_str()` 会**再复制整行一次**——每行 2+ 次堆分配/拷贝。
行型分解实测（同机同批，300k 行/型）：

| 行型 | 吞吐 | 单行 | vs 逐包 |
|---|---|---|---|
| 逐包（快路径） | 114.3 万行/秒 | 875 ns | 1× |
| FLOW | 72.9 万行/秒 | 1371 ns | **1.6×** |
| TRACE | 61.8 万行/秒 | 1619 ns | **1.9×** |

影响面：dashboard tailer 每 120ms 泵全部 TRACE/FLOW 行（演示时每包 3–4 行 TRACE）；
出口以高频率报 FLOW 时控制器侧线性放大。改法与 `feed_packet` 同构：手写
`parse_udec/parse_mac` 已存在，直接复用即可，FLOW 判定本体只有 2 次折叠乘。
预期该行型回到 ~900ns 量级（≥40% 收益）并消除逐行堆分配。

## 4 工程性收尾（P1-3 / P2）

1. **Makefile 自动依赖**（P1-3）：当前 `HDRS` 手工枚举 5 个头文件，新增头文件
   若忘改则**静默漏编**（改动不触发重编）。改为：

   ```make
   CXXFLAGS += -MMD -MP
   -include $(wildcard $(BUILD)/*.d)
   ```

2. **唯一构建警告**（P1-3）：`topo.cpp:18` 的 `(void)std::system(...)` 对 glibc 的
   `warn_unused_result` 无效（GCC 已知行为）。改 `int rc = std::system(...); (void)rc;`。
3. **dashboard 实时通道**（P2）：UI 每 700ms 轮询 `/api/state` 全量 JSON；
   换 **SSE**（`text/event-stream`，纯 HTTP，符合零依赖原则）可把事件延迟从
   ~820ms（轮询间隔+tailer 间隔）压到 tailer 间隔，且断线自动重连语义免费获得。
4. **`/metrics` 端点**（P2）：Prometheus 文本格式是纯文本协议——
   `mpv_packets_total{dir,verdict}`、`mpv_verify_us_bucket`、`mpv_rss_kb` 十余个指标，
   即可接入 Grafana 长跑观测；与「RSS 实时可见」（M5.16）同一动机的系统化版本。
5. **dashboard 集合无界**（P2）：`traced_h2/reported_h2`（`dashboard.cpp:70`）只在
   reset 时清空，长跑演示缓慢增长；给个 2¹⁶ 上界+世代清空与控制器口径一致。
6. **NonceWindow 取模回卷**（P2，微优化）：`see()` 每次 `(head+1) % cap_` 是一次除法
   （实测 28–32ns/次里占可观比例）；改分支回卷 `head+1==cap_?0:head+1`。

## 5 当代应用框架对照（每项均先过「零依赖是否被破坏」与「实测是否可行」两关）

### 5.1 内核数据面（对 §19.3 结论的两点修正）

§19.3 判定「内核加速只剩消 veth 跳数或 XDP/eBPF 下沉，而后者不可行（eBPF 无 128 位乘、
验证复杂度受限）」——**前半句成立，后半句对 AF_XDP 不成立**：

* **AF_XDP**：内核侧只需一个 `bpf_redirect_map` 的 XDP 程序（trivial），**验证计算
  留在用户态**（UMEM 收发环），完全不触碰「eBPF 指令模型」限制。veth 自内核 5.5+
  支持原生 AF_XDP，本机 kernel 7.0.0 无障碍；VM 已确认 XDP 符号齐备。
  收益面：消除每包 socket 路径（§19 实测剩余瓶颈正是 veth 协议栈路径），
  是 recvmmsg 之后下一档的合理台阶，工程量约等于一次 M5.13（周级）。
  **同时保留 recvmmsg 兜底**（与现有 `MPV_RX_RING` 环境变量开关机制同构）。
* **io_uring（IORING_OP_SEND 批量提交）**：热路径上最后一个未批量的 syscall 是
  **逐包 sendto**（RX 已 recvmmsg 批量）。io_uring 可把一批 TX SQE 一次提交、
  完成侧批量收割。对墙钟（串行唤醒链主导）预期增益有限，但对 µs CPU/行 是直接削减；
  kernel 7.0 完整支持（已确认 io_uring 未被 sysctl 禁用）。
  适合作为 AF_XDP 之前的低成本实验（≤2 天）。
* **eBPF 计算下沉**的再评估：64×64→128 乘可用 4 次 32 位乘合成，BLAKE2b 单块
  ~900 指令在 1M 指令上限内可行——「装不下」不严谨；但 verifier 复杂度、
  可维护性与 P4 表达力权衡后，**P4/BMv2 路线（已在下一步计划）优先级更高的判断不变**。
* **DPDK**：需绑核/大页/替换 netns 拓扑，超出原型边界；AF_XDP 是正确的中间档。

### 5.2 应用层

* **上报通道**：文件 tail 是有意的简化（可审计、崩溃安全、零依赖），**不建议整体
  换 gRPC**——文本解析 875ns/行快于任何序列化框架的编解码。值得做的是**可选并行
  通道**：UDS 流式 socket（`SOCK_SEQPACKET`，一包一行）给 dashboard 实时消费，
  文件仍是唯一事实源——演示事件延迟从 ~820ms 降到毫秒级，tailer 变成兜底。
* **C++20/23**（VM 实测 `-std=c++20` 全量编译零警告通过）：落地清单——
  `std::span`（解析函数签名去指针+长度）、`starts_with`（feed 前缀分发）、
  `std::byteswap`（头部编解码）、`std::jthread`（tailer/worker 线程自动 join）、
  `atomic::wait`（tpool 的 condvar → futex 等待，少一次锁往返）、
  `std::to_chars`（json_state 数值序列化去 ostringstream）。
  升级收益是**表达力与正确性**（性能上 to_chars/jthread 是小赢），黄金向量门槛不变。
* **质量基础设施**：本次验证过程证明三件事都值得入库——
  ① ASan+UBSan 构建 + tests 全量通过（本次已跑：干净）；
  ② **模糊测试目标**：自写 harness（附录 B）50 万次内即抓到 §1 的真缺陷——
    解析器 + 恶意输入正是本项目威胁模型的直接映射；C++ 侧零依赖可用
    「随机行生成循环 + ASan」形态（libFuzzer 若引入 clang 则进 CI）；
  ③ GitHub Actions：`O3+LTO 构建 → tests → ASan/UBSan → fuzz 冒烟 → e2e（self-hosted）`。
* **静态分析**：`gcc -fanalyzer` 本次全量通过（零告警）；clang-tidy 可进 CI。
* **部署形态**：演示依赖 `sudo make demo`；一个 `systemd` 单元或 README 化的
  `VM 快照说明` 比 Docker（netns/AF_PACKET 需特权容器）更贴合本项目。

## 6 明确不推荐的优化（诚实边界）

| 项 | 理由 |
|---|---|
| PGO、`-march=native` | §2.3 实测无增益 |
| 更弱哈希 / 减轮数 | 破坏随机预言语义与黄金向量；§16 下界论证仍成立 |
| 控制器 feed 多线程 | 175 万行/秒（官方口径）远超端到端需求两个数量级（§17.3 取舍依然正确） |
| 整体换 gRPC/protobuf | 文本快路径比序列化框架编解码更快；文件方案的可审计性是特性 |
| 全面 DPDK 化 | 超出原型边界；AF_XDP 才是对应的正确台阶 |

## 7 建议落地顺序

1. **P0-1/P0-2**（安全修复，半天）→ tests 增补对抗断言；
2. **P1-1 旗标 + P1-3 Makefile/警告**（半小时）→ 全量回归即收获 scan 2.6×；
3. **P1-2 FLOW/TRACE 快路径**（半天）→ 补行型吞吐断言；
4. **P2 按 UI/观测需要选做**；
5. **P3 io_uring TX 批量**（2 天实验，走 §19 方法学的参数解耦教训）→ 若 CPU/行 收益明确，
   再立项 **AF_XDP**。

```cpp
    d.paths.push_back(p); }
  Controller ctl(20260501, {d});
  for (unsigned long long i = 0; i < iters; ++i) {
    // ...按 shape 生成 "TRACE <mac> <sid> <in> <out> <tag> <nonce> <pos> <v>" 等
    //    字段随机、随机截断、越界 sid/port、纯随机字节行（完整源码见交付记录）
    ctl.feed(line);

}
```

> 建议入库为 `cpp/tests/fuzz_feed.cpp` + Makefile 目标 `make fuzz`
>（`-fsanitize=address,undefined` 构建，固定 60s 冒烟），CI 里每次跑。
