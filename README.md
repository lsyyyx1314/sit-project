# MPV-2 · 面向软件定义网络的高效多路径验证

湖南大学大学生创新创业训练计划（创新训练项目）原型系统。
**纯 C++17 实现——工程内没有任何脚本语言**（无 Python、无 Shell），依赖只有
g++ ≥ 11 与 make；拓扑用 iproute2 的 `ip` 命令搭建，交换机、控制器、验证器与
演示 APP 全部是本工程编译出的可执行文件。

## 这是什么

把路径验证的对象从「一条固定路径」扩展为「**一个合法路径集合**」：

- 数据包逐跳维护 **16 字节定长验证头**（不随跳数、路径数膨胀）；
- 出口上报控制器，O(1) 判定包是否走了合法路径集合中的某一条；
- 失败时**逐跳取证定位嫌疑交换机**（多故障同时报出全部嫌疑，支持黑洞失联发现）；
- **流级压缩（CFMV）**：出口按流聚合三元组，控制器每窗口一次判定，
  通信开销降至逐包上报的 0.46%–14%，且不引入漏检（对比概率采样路线）；
- 链路故障切换时候选集与转发表协同收敛，验证零误报。

## 快速开始

```bash
make deps       # 安装 g++ / make / iproute2（已装则跳过）
make            # 编译 7 个可执行文件（cpp/build/）
make test       # 黄金向量交叉校验 + 716 项功能/对抗/CFMV/重放/定位断言
make bench      # 攻击矩阵、多候选矩阵、性能与基线对比
sudo make e2e   # 七轮端到端：正常/标签错配/恶意改头/恶意重放/流级压缩/故障切换/多重故障
sudo make demo  # 演示 APP：浏览器打开 http://<主机>:8080
sudo make exp   # 11 组结题实验一键运行，自动生成 results/exp_report.md + SVG 图表
```

> `e2e` 与 `dashboard` 默认共用 `/tmp/mpv_run` 与 h1/h2 netns 名，不要同时运行；
> 多实例并行用环境变量隔离：`MPV_WORK=/tmp/mpv_x MPV_NS=x- sudo ./build/...`。

## 核心设计

把随机性放在**线性项**而非指数上——不需要「消去随机数」（申报书原式
`g^(w·s_m) ≡ f_s^w` 因欧拉定理恒真退化，伪造接受率 100%，已证伪并重构）：

```text
h    = H(nonce)                  公开哈希（BLAKE2b）
c_i  = (a_i + b_i·h) mod p       单跳贡献（端口密钥派生 a_i, b_i）
V    = Σ c_i·ρ^(i-1) mod p       逐跳累积，ρ 位置加权绑定顺序
E(P) = A_P + B_P·h               控制器期望值：与 nonce 无关，流建立时预计算
```

由此直接导出三层递进机制：

| 层 | 机制 | 效果 |
|---|---|---|
| BPMV | 候选集逐条校验 | 基础可验证性，O(k) |
| CPMV | tag 直接比对期望值 | **多条路径、一次判定**，O(1) 与 k 无关 |
| CFMV | 线性性 ⇒ `ΣV = N·A + B·Σh`，出口聚合 `(N, Σh, ΣV)` | **逐包 → 逐流**，判定与 N 无关，通信 0.46%–14% |

配套机制：nonce 窗口判重（O(1)，抗重放）、逐跳取证定位（首分歧 + 多故障 +
黑洞失联）、链路故障切换时候选集与转发表协同收敛。

## 性能指标（VM 实测，Ubuntu 24.04 / g++ 13）

**指标 1：判定时延（验证快）**

| 口径 | 数值 |
|---|---|
| tag 模式（CPMV） | **0.23–0.25 µs，与 k 无关**（k=1→64），吞吐 400 万次判定/秒 |
| scan 模式（BPMV 对照） | 0.43 µs @ k=64（随 k 线性） |
| CFMV 流级判定 | 0.05 µs，与窗口 N 无关（N=4096） |
| 期望预计算 | 0.80 µs @ h=32（流建立时一次） |

**指标 2：处理吞吐（开销低）**

| 口径 | 数值 |
|---|---|
| 控制器上报处理 | **175.5 万行/秒**（0.57 µs/行，含解析 + 双口径判定 + 判重） |
| 流级压缩 | 窗口 64 → 判定次数压缩 64×；通信 0.46%–14% |
| 数据面管道 | ≈2800–3400 行/秒（用户态 AF_PACKET；>90% 墙钟在内核 veth 往返，见报告 §15/§19） |

**正确性与对抗**（十类结构性攻击 ×10⁴ 次全部 100% 检出、诚实流 100% 通过）：

| 项 | 结果 |
|---|---|
| 黄金向量交叉校验 | 612 项逐位一致（与早期独立参考实现） |
| 断言总数 | 716 项，0 失败 |
| 多候选 k=2/8/16 | 攻击检出 / 诚实接受 均 100% |
| 定位成功率（exp[9]） | 随机故障位置 1500/1500 嫌疑集精确命中、零误标；集合外篡改只有取证能定位（100% vs 无取证 0%） |
| 同测试床基线（exp[10]） | 逐跳 MAC 链（Icing 类）k=64 时 390.9µs vs 本方案 0.3µs（**≈1300×**）；概率采样（Atlas 类）负载 1/64 漏检 98.4%，CFMV 全检出 |
| 规模扩展（exp[11]） | h=4→32、k=1→64：开销恒定、检出率 100% |
| 重放窗口 | 43 ns/次（O(1)），窗口内重放检出 1000/1000 |
| 并发（exp[1]） | 4 线程池 3.16× 加速（`--threads` 可调） |
| 常驻内存（实测） | dashboard RSS ~5.2MB（`/api/state` 实时可见）；exp 进程峰值 VmHWM 13.7MB |
| 端到端 R1–R7 | 七类场景全部通过（含故障切换零误报、双故障定位 {s1,s3}） |

优化过程与下界论证见设计报告 §13–§19：安全修补 → 健壮性 → 数据面剖析 →
计算时间下界（判定 = 1 次公开哈希 + ~5ns 域运算）→ 内存账本 → 线程池 →
内核加速受控实验（TPACKET_V3/QDISC_BYPASS/SO_BUSY_POLL 实测否决，负结果矩阵入册）。
