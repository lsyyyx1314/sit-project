# MPV-2 — SDN 多路径路径验证

数据包在转发过程中逐跳维护一个 **16 字节定长验证头**，出口上报控制器；控制器据此判定
数据包是否沿**合法路径集合**中的某一条转发，失败时**逐跳取证定位嫌疑交换机**（多故障
同时报出全部嫌疑），支持**流级压缩判定**（逐包 → 逐流，一次判定一整窗）。

纯 C++17 实现，无脚本语言；依赖仅 g++ ≥ 11 与 make。拓扑用 iproute2 的 `ip` 命令搭建，
交换机、控制器、验证器与演示 APP 均为本工程编译出的可执行文件。

## 快速开始

```bash
make deps       # 安装 g++ / make / iproute2（已装则跳过）
make            # 编译 7 个可执行文件（cpp/build/）
make test       # 黄金向量交叉校验 + 727 项功能/对抗/CFMV/重放/定位断言
make bench      # 攻击矩阵、多候选矩阵、性能与基线对比
sudo make e2e   # 七轮端到端：正常/标签错配/恶意改头/恶意重放/流级压缩/故障切换/多重故障
sudo make demo  # 演示 APP：浏览器打开 http://<主机>:8080
sudo make exp   # 11 组实验一键运行，自动生成 results/exp_report.md + SVG 图表
```

> `e2e` 与 `demo` 默认共用 `/tmp/mpv_run` 与 h1/h2 netns 名，不要同时运行；
> 多实例并行用环境变量隔离：`MPV_WORK=/tmp/mpv_x MPV_NS=x- sudo ./build/...`。

## 设计

把随机性放在**线性项**而非指数上，不需要「消去随机数」：

```text
h    = H(nonce)                  公开哈希（BLAKE2b）
c_i  = (a_i + b_i·h) mod p       单跳贡献（端口密钥派生 a_i, b_i）
V    = Σ c_i·ρ^(i-1) mod p       逐跳累积，ρ 位置加权绑定顺序
E(P) = A_P + B_P·h               控制器期望值：与 nonce 无关，流建立时预计算
```

| 层 | 机制 | 效果 |
|---|---|---|
| BPMV | 候选集逐条校验 | 基础可验证性，O(k) |
| CPMV | tag 直接比对期望值 | 多条路径、一次判定，O(1) 与 k 无关 |
| CFMV | 线性性 ⇒ `ΣV = N·A + B·Σh`，出口聚合 `(N, Σh, ΣV)` | 逐包 → 逐流，判定与 N 无关，通信 0.46%–14% |

配套机制：

- 验证头恒定 **16 字节**（nonce 56 + V 64 + tag 8）
- nonce 窗口判重 O(1)（≈30 ns/次，分支回卷），抗重放
- 上报行边界校验（M5.18）：越界 sid/端口/tag 的取证与上报行一律拒绝、单 nonce
  取证条目设上界——恶意交换机无法用伪造上报击穿控制器（模糊测试把关）
- 逐跳取证定位：首分歧 + 多故障全部嫌疑 + 黑洞失联发现
- 链路故障切换时候选集与转发表协同收敛，验证零误报
- 线程池复用、零堆分配热路径、RSS 实时可观测

## 性能（VM 实测，Ubuntu 24.04 / g++ 13；2026-11-15 起 `-O3 -flto` 构建）

| 指标 | 数值 |
|---|---|
| 判定时延（tag/CPMV） | **≈0.30 µs，与候选数 k 无关**（k=1→64 实测 0.27–0.33），≈330 万次/秒 |
| 判定时延（scan/BPMV） | 0.28 µs @ k=64（M5.18 `-O3 -flto` 后；同机 A/B 自 0.69 µs 优化 ≈2.5×） |
| 流级判定（CFMV） | 0.04 µs，与窗口 N 无关（N=4096） |
| FLOW/TRACE 行解析 | 手写快路径 ≈440 / 325 ns/行（原 istringstream 慢 3.1×/5×，M5.18） |
| 控制器上报吞吐 | **175.5 万行/秒**（0.57 µs/行，含解析+双口径判定+判重） |
| 通信开销 | 流级聚合降至逐包上报的 0.46%–14%（窗口 250–8） |
| 验证头 | 恒定 16B（逐跳追加式 h=16 时 64B，省 75%） |
| 攻击检出 | 十类结构性攻击 ×10⁴ 全部 100%；诚实流 100%；多候选 k=2/8/16 均 100% |
| 定位成功率 | 随机故障位置 1500/1500 嫌疑集精确命中、零误标 |
| 基线对比 | 逐跳 MAC 链 k=64 时 390.9µs vs 0.3µs（≈1300×）；概率采样负载 1/64 漏检 98.4%，本方案全检出 |
| 并发 | 实验 4 线程池 3.16× 加速（`--threads` 可调） |
| 常驻内存 | dashboard RSS ~5.2MB（API 实时可见） |
| 端到端 | 七类场景全部通过（含故障切换零误报、双故障定位 {s1,s3}） |

## 已知局限

- 安全性基于 PRF 假设与 1/p 猜中概率，未做密码学归约；128-bit 域为直筒替换
- 对比基线为同测试床算法级实现 + 解析口径，未复现完整外部系统
- 用户态 AF_PACKET 数据面吞吐比硬件低 2–3 个数量级（计算本身 ~2–5µs/跳，瓶颈在内核路径）
- 控制器为半在线（场景级候选集热切换，无持续拓扑发现）
